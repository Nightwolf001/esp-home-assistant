Lesson 0001 · Stage 0: Toolchain

Install ESP-IDF and say hello

About 30 minutes, most of it downloads. Hardware: one DFR1154 and a USB-C data cable.

The win: your own board prints Hello world! to your terminal, using firmware you built and flashed yourself.

You write no code today. The skill is the loop you will run hundreds of times in this project: build, flash, monitor. In web terms: compile, deploy to a device with no operating system, then tail its logs over a cable.

What you are installing

ESP-IDF is Espressif's own framework for its chips. It is three things: a C library for the hardware, a cross-compiler that runs on your Mac but produces code for the ESP32-S3, and idf.py, a command that drives building and flashing (ESP-IDF Get Started). Since v6.0 the supported way to install all three is the Espressif Installation Manager, EIM (macOS setup).

Steps

  1. Install the prerequisites and EIM with Homebrew. 
    brew install libgcrypt glib pixman sdl2 libslirp dfu-util cmake python
brew tap espressif/eim
brew install eim
  2. Install ESP-IDF. This fetches the latest stable release and its toolchain. 
    eim install
    Wait for Successfully installed IDF. EIM then prints an activation command that starts with source. Copy it somewhere: you need it in every new terminal.
  3. Activate the environment by running the command EIM printed. It looks like this, with your own path and version: 
    source "/Users/you/.espressif/tools/activate_idf_v6.1.sh"
    Check it worked: 
    idf.py --version
  4. Copy Espressif's example into this repo. Run this from the repo root. ESP-IDF cannot handle spaces in paths, so check the repo's own path has none. 
    cp -r $IDF_PATH/examples/get-started/hello_world firmware/01-hello
cd firmware/01-hello
  5. Tell the build which chip you have. 
    idf.py set-target esp32s3
  6. Plug in the board and find its port. On macOS the port name starts with /dev/cu. 
    ls /dev/cu.*
    Run it once unplugged and once plugged in. The name that appears is your board.
  7. Build, flash and monitor in one go. Replace PORT with the name from the previous step. 
    idf.py -p PORT flash monitor
    The first build takes a few minutes. Then you should see Hello world!, some facts about the chip, and a countdown to a restart. Leave the monitor with Ctrl+].
If it does not go to plan, stop and tell me exactly what you see. Two things I could not test without the board:
  • Flashing cannot connect. Hold BOOT, tap RST, release BOOT, then run the flash command again. That forces the chip into download mode.
  • Flashing works but the monitor stays silent. Say so. It means this board needs its log output pointed at the USB port, which is a one-line setting and a good first look at menuconfig.
